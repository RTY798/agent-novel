# v11.0 框架升级方案 — 三型分流 + 最小化流程

> 基于 v10.3 的实战反馈（Ch.21-78）和架构审计。不推翻 v10.3 的积累，改变的是**流程结构**和**判断优先级**。

## 0. 升级总览

| 维度 | v10.3 | v11.0 |
|------|-------|-------|
| 流程结构 | 一刀切8步，所有章节同一套 | 三型分流，章型决定流程 |
| 核心工具 | 核心卡片→技法选择→信号词→4e | **唯一画面测试**提到第0步，三型各配最小流程 |

## 1. 入口：章型判断（第0步，写前必做）

写第一个字之前，先回答一个问题：

> **这一章的主要功能是什么？**

| 你的回答 | 章型 | 代码 |
|---------|------|------|
| "展现角色的内心变化/情感状态/人际关系" | 🎭 情绪章 — A型 | 走A型流程 |
| "推进事件/发生冲突/做决定/打斗" | ⚔️ 动作章 — B型 | 走B型流程 |
| "传递信息/世界构建/过渡/谈判/补给" | 🏗️ 功能章 — C型 | 走C型流程 |

**判断不准时**：问第二个问题——"读者读完这一章，最深的记忆会是一个感觉、一个画面，还是一个信息？"
- 感觉 → A型
- 画面/动作 → B型  
- 信息 → C型

**选择之后**：A型不查B型的检查项，B型不查C型的检查项。禁止跨型套用。

## 2. 🎭 A型流程 — 情绪章（6步）

**适用**：Ch.46「第一夜·房间」类——角色内心变化、情感状态、群像独处

### 2.1 第0.5步：唯一画面测试（写前必做）

> ⚠️ **v11.0 最核心的改动。唯一画面测试从质检环节移到写前。**

回答：**"读者合上这一章，眼前会留下哪一张画面？"**

规则：
- 必须是一个**感官的、具体的、唯一的**意象
- 不是氛围（"悲伤"），不是概念（"希望"），不是事件（"他们洗了澡"）
- 是"魏小丁哼了一声。不为什么。只是听到自己还在"这个级别的具体
- 如果说不出来→这一章的核还没找到→不要开始写

然后判断：这个画面应该在正文的什么位置？
- 如果画面在结尾附近 → 这一章是**累积型**（逐步推向那个画面）
- 如果画面在中间 → 这一章是**环绕型**（那个画面是核心，其他段落环绕它）
- 如果画面不在正文里 → 重写这一章的概念，让正文能产生这个画面

**唯一画面测试通过之后，才进入A型流程。未通过→退回想，不写。**

### 2.2 身体接缝（3条，不是5条）

> v10.3要5条。v11.0减到3条。原因是：5条时第4第5条开始凑数，3条时每条都得是真实的。

读上一章全文。找到3条身体接缝：

```
Ch.N 角色A 身体状态 → Ch.N+1 接住了吗？
Ch.N 角色B 身体状态 → Ch.N+1 接住了吗？
Ch.N 角色C 身体状态 → Ch.N+1 接住了吗？
```

**找3条够了的标准**：如果第4条要想10秒以上才能找到 → 不需要第4条。3条真实的比5条凑数的有用。

### 2.3 情感债务检查（1条）

上一章结尾谁欠了谁一笔未清的账？（未说完的话、回避的眼神、一句重话、一个没完成的动作）

**找到之后，只做一件事**：在本章中让这笔债**扭曲角色的第一个相关行为**。

> 如果债务在一章内没有导致任何行为变形 → 这个债务不存在，退回去重新找。

### 2.4 写（不查技法表，不填核心卡片）

A型章不查技法表。不填核心卡片的"场景核"部分。

**规则**：
1. 唯一画面已知（第0.5步）
2. 身体接缝已知（3条）
3. 情感债务已知（1条）
4. 焦距已知（贴肩/借眼/半空，由唯一画面决定）

**写。信任自己。** A型章的质量不由技法选择决定，由"是否找到了对的瞬间并且没有挡住它"决定。

**唯一可用的写中检查**：如果写到某个段落感觉不对→停→不是去查技法表 → 是问"这里是按我的直觉在走，还是在按公式在走？"

### 2.5 A型核验（3项，不是10项）

写完后，只查这3项：

**① 唯一画面在正文里吗？位置对吗？**
如果答案是否→重写那一部分。如果画面不在正文里→整章重写。

**② 身体接缝全接了吗？**
每条身体接缝在本章中都有对应的身体状态延续/变化。漏了一条→补上。

**③ 这一章有没有创造出一种之前没出现过的写法？**
不是"句子好不好"，是"这个处理方式我在之前的78章里见过吗"。如果答案是"见过"→找到那个位置，改成新的处理方式。

> **不查**：的时候、光从、破折号功能、副线物品轮换
> **不查**：4a-c（QC自动扫描仍运行，但不作为硬性PASS/FAIL）
> **不查**：核型匹配、技法使用率

## 3. ⚔️ B型流程 — 动作章（5步）

**适用**：Ch.21「不犹豫」类——事件推进、战斗、决定、道德选择

### 3.1 唯一画面测试（同A型，但重点不同）

B型的唯一画面通常是**动作的最后一帧**——"砖扣在地上，花看不见了"或"车走了，烟越来越细"。

**B型唯一画面的位置规律**：95%在章的最后一个场景。如果不是→确认这个画面是否真的属于B型（可能其实是A型选了B型流程）。

### 3.2 节奏地图（代替核心卡片）

不填核心卡片。改画节奏地图：

```
场景1：______（起点·正常节奏）
场景2：______（前奏·渐快）
场景3：______（核心冲突·最慢——因为要拆动作）
场景4：______（回落·渐快）
场景5：______（余震·最慢——因为要留情绪）
```

**关键**：核心冲突场景（最慢）和余震场景（最慢）**不能相邻**。如果相邻→中间缺一个"喘气"的场景。

**字数分配规则**：核心冲突场景占整章35-45%，余震场景占15-20%，其余场景共同占35-50%。

### 3.3 慢镜头标记

在节奏地图上标出**唯一一个需要慢镜头**的位置——通常是核心冲突场景中动作完成的那一瞬间。

三拍结构（同v10.3 ⑨，但只用在标记的位置，不扫描全章）：
```
准备：蓄力/瞄准/犹豫（长句）
放大：动作的瞬间细节（中句）
释放：结果（短句）
```

**规则**：一章最多用一次慢镜头。用两次 → 两次都失去效果。

### 3.4 写（允许查技法表，但有限制）

B型章可以查 `seven-knives.md` 和 `nucleus-to-technique-index.md`，但**只查一次**——在节奏地图画完之后，选一个场景指定一个技法。其余场景不分配技法。

**写中检查**（只查一项）：
> **这个场景是真的在推进故事，还是在填充字数让故事到达下一个情节节点？**

如果答案是"填充"→删除或合并到上一个场景。不写。

### 3.5 B型核验（3项）

**① 节奏地图兑现了吗？**
核心冲突场景是否确实是全章最慢的部分？余震场景是否预留了足够的空间？如果写出来的节奏和地图不一样→不需要改正文，但需要更新地图来理解自己实际写了什么。

**② 慢镜头用在了最重的位置吗？**
不是"慢镜头本身好不好"，是"位置对不对"。如果慢镜头的位置不是全章情感最重的位置→删掉慢镜头，移到真正需要它的位置，原来的位置白描处理。

**③ 标题和正文在说同一件事吗？**
Ch.21 的教训：标题"不犹豫"，正文说"不犹豫但也不麻醉"——标题落后正文。读一遍标题，再读一遍正文的最后一句话。如果两者不在同一个立场上→改标题。

## 4. 🏗️ C型流程 — 功能章（3步）

**适用**：Ch.78「东河镇」类——谈判、交易、补给、世界构建、过渡

### 4.1 世界逻辑检查（代替唯一画面测试）

C型章不需要唯一画面。需要的是：

**3个问题**（回答必须能说服自己）：
1. **这个场景在末世里合理吗？**——为什么这个镇子还活着？他们的经济系统是什么？为什么愿意跟陌生人交易？
2. **每个出场角色有没有"属于自己"的一刻？**——不只是功能性反应（卖家、买信息、指路），是他们做了一个跟主线无关但暴露个性的动作。
3. **信息密度够吗？**——这一章如果只传递了"他们拿到了油和种子"这一个信息→太薄了。至少要在对话和细节中包裹3个以上关于末世世界的额外信息。

**回答不能说服自己→不写。说明对这一章的世界构建准备不足。**

### 4.2 写（规则最少的一类）

C型章不查任何技法表。不填核心卡片。不做记忆激活。

写中唯一检查：
> **节奏是否和前后章有区别？**

C型章的节奏必须和它前后的A型或B型章不同。如果前章是紧凑的A型，C型要更散一点、句子更长一点、对话更多一点。目的是让读者的阅读体验有高低变化。

### 4.3 C型核验（3项）

**① 每个角色有自己的时刻吗？**
不要求"情感深度"，要求"有一个只属于这个角色的反应"——哪怕是老头剥豆子时没抬头。

**② 信息包裹够吗？**
至少3个关于世界的信息是通过"顺便"的方式传递的（不是在信息交代段落里，是在对话的缝隙里）。

**③ 这一章有没有一种"日常的诡异"？**
末世17天后的正常生活——这个正常本身是它最不对劲的地方。如果这一章读起来只有"他们拿了东西就走了"→没有抓住C型章的核心价值。

## 5. 新增：反公式层（三型通用，v11.0 新增）

### 5.1 自创公式检测

v10.3 的信号词表只检测AI通用腔。v11.0 增加自创公式检测——检测你自己创造的新套路：

**每次写完之后，问自己三个问题**：

1. **"这一章里，有没有一个动作/物品/句式我在之前的10章里用过？"**
   - 打火机出现了几章了？打火机不在的时候有没有用一个替代品顶上？
   - "XX在口袋里/银色的/焐热的"这个句式序列出现了几次了？
   - 手指松开/攥紧/放平这个动作序列在最近几章出现了几次？

2. **"有没有一个情感处理方式，我最近3章都在用？"**
   - 不说话×不说话×不说话 —— 第三次还是同样的"不说话"，还是三种不同的"不说话"？
   - 倒扣/隐藏/反转 —— 同一个象征动作模式在连续使用吗？

3. **"这一章开头的方式，和上一章开头的方式，基本框架一样吗？"**
   - 都是"灯关了。/天黑了。/车停了。"短句+换行开头？
   - 都是先写环境再写人？
   - 连续3章以上同一个开头模式 → 第四章必须换

**自创公式检测不过的处理方式**：
- 第一次发现 → 改掉那一处
- 连续第二次发现同一个公式 → 整段重写，不修改
- 第三次发现同一个公式 → 这一章应该换章型处理（A型改B型，或B型改C型）

### 5.2 物品轮换硬性限制

v10.3 有副线物品检查（第⑤项）。v11.0 升级为**物品时间线检查**：

| 物品 | 最近出现章节 | 上次变化 | 下次出现时应有的变化 |
|------|------------|---------|-------------------|
| 打火机 | Ch.__ | ______ | ______ |
| 菜单本 | Ch.__ | ______ | ______ |
| 狗牌 | Ch.__ | ______ | ______ |
| 红花油 | Ch.__ | ______ | ______ |

**规则**：
- 同一物品连续2章出现 → 第3章禁止出现
- 物品每次出现必须有变化（变旧/变脏/变位置/变功能/变温度），不写静止的物品
- 物品的消失也是一种变化——当读者发现"打火机这章没出现"时，消失本身就产生了意义

## 6. 新增：3+1熔断机制（三型通用，硬性）

### 6.1 规则

每写3章，第4章**完全不按流程走**。

- 不判断章型
- 不填核心卡片
- 不做身体接缝
- 不查技法表
- 不进行4e核验
- 不运行QC
- 不更新信号词表

**第4章的唯一质控**：出声读一遍，回答一个问题——"这一章里有我写得不满意的地方吗？是哪一段？为什么？怎么改？"

### 6.2 为什么

v10.3 的最高上限来自你绕过框架的时刻（Ch.46 花洒、Ch.21 安凯尔的自白）。框架能稳定你的下限，但稳定的框架不能产生突破。

第4章给你一个"合法的破格通道"。它不是"偷懒日"——实际上它比跟着流程写更难，因为没有清单可以依赖。但这一章的价值在于：**它让你练习在没有规则的情况下做出判断。**

### 6.3 第4章的类型选择建议

第4章优先选择你**最不擅长**的章型：
- 如果你A型写得多 → 第4章写B型或C型
- 如果你习惯情绪驱动 → 第4章写一个纯功能性的C型
- 如果你习惯动作驱动 → 第4章写一个静默的A型

目的是让第4章强迫你使用不常用的写作肌肉。

## 9. v11.0 设计原理总结

**三个核心判断，替代 v10.3 的一个"全流程"假设：**

1. **不是所有章节都需要同样的准备。** A型需要情绪准备，B型需要节奏准备，C型需要逻辑准备。用同一套准备流程处理三类章型，是对前两类的不够和对第三类的过度。

2. **不是所有检查都带来价值。** v10.3 的12项检查中，有7项在A型章中的发现率为零。每项检查都有成本（注意力和信任感），当收益低于成本时，检查应该被移除而不是保留。

3. **不是所有好章节都来自流程。** v10.3 最好的章节与流程的关系最弱，与"作者在关键时刻做出正确判断"的关系最强。v11.0 不是增加更多的流程，而是给直觉留出结构化的空间——包括第4章的完全自由和A型的技法表豁免。

**一句话：v10.3 确保每一章都及格。v11.0 确保每三章里有一章有机会优秀。**

## 10. 外部精华融入（基于2025-2026年AI写作领域系统调研）

> 以下内容综合自 InkOS（26维审计系统）、Autonovel（对抗式编辑流水线）、TianMing Skill（渐进披露框架）、TRACE（写-审-改工作流）、Sudowrite Pro Best Practices、CAFES 协作框架 等6个前沿系统的设计精华。

### 10.1 文风指纹系统（借鉴 InkOS + 行业实践）

**问题**：当前框架用禁用词表和规则来消除AI味，但规则是通用的，不针对你的个人风格。结果是你消灭了AI腔，但没有建立自己的声音。

**方案**：在项目初始化时建立**文风指纹文件** `style-fingerprint.md`。

建立方法（一次性的，建完自动引用）：

从你已写好的章节中提取以下数据：

| 维度 | 测量方法 |
|------|---------|
| **平均句长** | 统计300句的中位数句长（不是平均，中位数抗极端值） |
| **句长分布** | 短句(≤8字)百分比 / 中句(9-25字)百分比 / 长句(≥26字)百分比 |
| **类型-标记比(TTR)** | 去重词数 ÷ 总词数 × 100（衡量词汇丰富度） |
| **段落长度中位数** | 统计100段的中位数字数 |
| **感官通道分布** | 视觉/触觉/听觉/嗅觉/味觉 在最近10章中的出现比例 |
| **高频实词** | 去掉虚词后出现频率前20的名词和动词 |
| **叙述 vs 对话比** | 叙述字数 ÷ 对话字数 在最近5章中的比例 |
| **对话打断频率** | 每千字中对话被动作/环境/沉默打断的次数 |

**使用方式**：写每一章前，将`style-fingerprint.md`的内容注入Writer prompt第一段。不要求严格遵守，但要求"知道自己的基准线在哪里"。

**更新规则**：每10章更新一次，观察数据变化——如果你发现句长中位数在10章内显著变化，说明风格在漂移。

### 10.2 对抗式修改循环（借鉴 Autonovel + Karpathy Autoresearch）

**问题**：当前框架的质检是"检查并修改"，是线性的。没有"生成多个版本→评分→择优→丢弃差版本"的循环。

**方案**：在B型章（动作章）中引入**对抗式循环**：

```
第1轮：写 → 自评(1-5分) → ≥4分保留，<4分重写
第2轮：重写版 → 自评 → 和上一版对比 → 取高分版
第3轮：如果两版分数都≤3 → 换章型处理（B→A或B→C）
```

**规则**：
- 不是每章都用。仅B型章使用，且每3章最多用1次（防止过度优化）
- 评分维度只有**一个**："这一章的核心画面在读者脑中够清晰吗？"——不是语言好不好，是画面清不清晰
- 第3轮仍失败→换章型。说明这个内容不适合用B型处理

### 10.3 渐进披露（借鉴 TianMing Skill 的协议路由）

**问题**：当前框架要求每次加载所有文件（MASTER_SETTING + current_state + 前3章 + 多份reference）。上下文消耗大，且无关信息分散注意力。

**方案**：按章型控制文件加载范围：

| 章型 | 必读 | 必不读 |
|------|------|--------|
| A型（情绪） | MASTER_SETTING + 前1章全文 + nucleus-first-method.md + style-fingerprint.md | seven-knives.md（读它会导致在A型章里用技法） |
| B型（动作） | MASTER_SETTING + current_state + 前1章摘要 + seven-knives.md + nucleus-to-technique-index.md | style-fingerprint.md（读它会导致过度修饰） |
| C型（功能） | current_state + 世界设定相关文件 | nucleus-first-method.md（C型不需要核） |

**token预算规则**：
- A型：~60%用于加载+准备，~40%用于写作
- B型：~40%用于加载+准备，~60%用于写作（动作章需要更多生成空间）
- C型：~30%用于加载+准备，~70%用于写作（C型信息密集，需要更多输出空间）

**核心原则**：不加载本章用不到的协议。不把技法文件喂给情感章，不把风格文件喂给动作章。

### 10.4 双角色自审（借鉴 Autonovel 的双角色评审 + InkOS 的审计维度）

**问题**：当前4e核验是单一视角的清单勾选。没有"从不同身份读同一章"的多维反馈。

**方案**：在3+1熔断机制中，第4章（免检章）写完后，用**两个身份**读同一章：

> **身份一：普通读者**
> 问：这一章哪里让我想跳过去？为什么那一处让我出戏了？
>
> **身份二：编辑**
> 问：这一段和上一段的衔接在哪里断了？这个角色的动机在场景中有没有被行为证实？

**规则**：
- 只问不答——问题是用来引导重读的，不是用来写报告的
- 如果两个身份都指出了同一个问题→那一处必须改（双角色确认的bug比单视角可靠）
- 如果两个身份指出的问题不同→改那个让你更像"读者"身份指出的问题（编辑的挑剔可以留到下一轮，读者的出戏必须立刻修）

### 10.5 平台检测与反AI探测层（借鉴 InkOS 的 26 维 + AI-tell 检测）

**问题**：番茄小说的AI检测越来越严。当前框架的禁用词表（感到/觉得/仿佛）对平台级别的AI检测不够。

**方案**：在QC环节增加**平台AI检测模拟**。当你要发布到番茄小说时，额外扫描以下高阶AI特征：

| 高阶AI特征 | 检测方法 | 修复 |
|-----------|---------|------|
| **段落等长** | 连续5段字数标准差 < 30 → AI嫌疑 | 随机合并/拆分段落，打乱长度 |
| **套话密度** | "不禁/忽然/竟然/宛如/猛地"每3000字 > 1次 → AI嫌疑 | 替换为具体行为描述 |
| **公式化转场** | "时间来到/与此同时/就在这时/就在这时"连续使用 → AI嫌疑 | 删除转场词，直接切换场景 |
| **列表式结构** | 连续3句以上同句式开头 → AI嫌疑 | 改变至少2句的句式结构 |
| **对话标签单一** | 全章对话标签全部是"XX说" → AI嫌疑 | 混合使用动作标签、无标签、省略标签 |
| **无错别字** | 整章零错别字 → 反而可疑 | 故意保留1-2处符合角色习惯的"错别字"（如方言发音） |

**规则**：
- 这层检测仅在你准备发布前运行，不写入写中流程
- 检测结果不判断"好不好"，只判断"像不像AI写的"
- 修复原则：一次改一处，不要全章"去AI化"——过度去AI化会产生新的公式

### 10.6 质量熔断：70% 阈值（借鉴行业共识）

**问题**：当前框架允许3轮QC修改。但没有"何时停止修改"的信号——有些时候改3轮不如接受现状。

**方案**：引入**70%阈值规则**：

> **如果一章通过了QC、通过了3项核验、通过了反公式检测——但它仍然感觉"不够好"——问问自己：**
> **这一章是70%到位了吗？**

如果是：
- 70% 到位 + 通过了所有检查 = 过。下一章。
- 70% 到位但有一项检查没过 = 只修那一项。不全面重写。
- < 70% 到位 + 检查全过 = 说明检查项没有抓到真正的问题（罕见，但确实会发生）。此时不走检查项，走自己的判断。

**为什么是70%**：过度迭代（15轮以上的微调）会磨掉AI输出中的陌生感和随机性——那些让读者觉得"不是AI写的"的特质正是来自没有被完全规范化的部分。

## 11. 深度融入（基于2026年前沿研究的第二轮注入）

> 以下内容综合自 Novel-Forge（21道Guard门禁+Agent陪审团）、NarrativeLoom（概率陷阱+BVSR理论）、DeepWriter（AAAI 2026多智能体合著）、StoryScope（叙事指纹研究）、事件冷却矩阵、三层记忆架构等最新成果。

### 11.1 概率陷阱认知层（借鉴 NarrativeLoom CHI 2026 + 马煜曦研究）

**核心认知（必须内化，不只是知道）**：

> **AI 的"最可能续写" = 创意的"最无聊选择"。**

这不是偶然，是 LLM 的训练目标决定的——模型被训练去预测给定上下文后最可能出现的下一个词。这意味着它的自然倾向是落在训练数据的**统计中心**，避开偏离均值的"异常点"。而好故事需要的恰恰是异常点：亚里士多德所谓的"突转"（peripeteia）——出乎意料却又合乎逻辑的戏剧性转变。

**对你的写作意味着什么**：

| 你的习惯倾向（AI的自然选择） | 你需要主动选择的（反概率） |
|---------------------------|----------------------|
| 让角色做"最合理"的事 | 让角色做"符合他性格但出人意料"的事 |
| 让冲突沿着最直接的路径解决 | 让冲突绕一个弯，经过一个意外的障碍 |
| 让对话直接回答对方问题 | 让对话回答的不是对方问的那个问题 |
| 让章节的功能单一明确（要么情绪要么推进） | 让一章同时做两件看似矛盾的事 |
| 让情节转折有充分铺垫 | 让转折在铺垫的缝隙中突然发生 |

**实操规则**：写完每一章后，找出3处"读者最可能预判到的走向"，然后问——"这3处里，有没有至少1处我可以换成读者预判不到的走向？" 有→换。没有→这一章太安全了。

### 11.2 叙事指纹防护层（借鉴 StoryScope UMD + Google DeepMind 2026）

**StoryScope 研究的关键发现**（61,608篇故事的大规模实验）：

> **仅凭叙事结构特征即可 93.2% 准确率区分 AI 与人类写作。改变词汇、删禁词、调整句长——这些表层修改几乎不改变叙事指纹。**

人类 vs AI 最显著的差异：

| 维度 | AI 故事 | 人类故事 | 差距 |
|------|---------|---------|------|
| 无线性支线（只有主线） | 79% | 57% | +22% |
| 直接点明主题/道德 | 77% | 52% | +25% |
| 通过生理感受传递情绪 | 81% | 38% | +43% |
| 主角选择的道德模糊性 | 38% | 59% | -21% |
| 主角驱动结局 | 69% | 46% | +23% |
| 使用明确情绪标签 | 8% | 29% | -21% |
| 打破第四面墙 | 7% | 28% | -21% |

**对你的写作意味着什么**：

你现在的写作（读Ch.21/46/78的观感）已经比大部分AI小说好很多——你的叙事中有道德模糊性、有支线、有不直接点明的主题。但问题在于：

1. **生理感受传递情绪的比率偏高**（81%是AI水平——你确实大量使用身体细节承载情绪，这是你的优点也是AI指纹）
2. **主线驱动过于明确**——每一章都"有用"，没有"闲笔"
3. **情绪标签使用偏低**——偶尔直接写"他很难过"不是错误，反而更接近人类写作

**新增规则**：
- 每章至少保留1处直接的情绪标签（"他很难过""她很害怕"——不是退步，是人类指纹）
- 每3章至少有1章包含一段"对主线无推进的闲笔"（一段环境描写、一个配角的无关回忆、一件与剧情无关的小事）
- 每5章至少有1次"道德模糊选择"——主角做了一个在全局上看不是最优、但在他的认知局限里合理的选择

### 11.3 Story Contract 机制（借鉴 Novel-Forge）

**问题**：当前框架的"核心卡片"是写前填的，但写完没人检查"当时答应的做到了没有"。

**方案**：引入 **Story Contract**——写前承诺本章要完成的事，写后核验。

**写前承诺（3项，不可多）**：
```
本章合同：
1. 角色A在本章结束时，对角色B的态度从___变成___
2. 本章结束时，___这个未解决的问题依然悬而未决（反向刹车）
3. 读者会带走的一个画面是：___
```

**写后核验**：
- 合同1兑现了吗？→ 没兑现→是剧情需要还是忘了？
- 合同2兑现了吗？→ 如果所有问题都解决了→违反反向刹车规则
- 合同3兑现了吗？→ 画面在正文里吗？位置对吗？

**规则**：
- 合同项数固定为3，不多不少。3项迫使你选出最重要的。
- 合同内容在三型间有差异（A型重内心变化，B型重事件结果，C型重信息传递）
- 写后核验 3 项全 PASS → 过。2 项 PASS 1 项 FAIL → 修那一项。≤1 项 PASS → 整章有问题

### 11.4 反向刹车机制（借鉴 Novel-Forge + 行业共识）

**问题**：v10.3 的框架没有防止"提前解决核心冲突"的机制。结果是好写的章被优先写，重要的冲突被提前消耗。

**方案**：

> **非终局章节禁止解决主线核心冲突。**

具体规则：
- 每章必须**新增至少1个未解决的次要问题**（悬念、冲突、悬而未决的选择）
- 核心冲突（本卷、本弧线的主要矛盾）**禁止**在非终局章节中解决
- 如果一章结束时所有问题都被解决了→这一章违反了反向刹车

**反向刹车检查清单**（写后必查）：
```
□ 本章开始时存在的冲突，结束时是否全部解决？→ 如果是，太早了
□ 本章新增的未解决问题数量 ≥ 0？→ 零意味着是"消耗章"
□ 本章是否触及了不该在本阶段触及的核心冲突？→ 如果是，留到卷终
```

### 11.5 事件冷却矩阵（借鉴 Novel-Forge 冷却机制 + InkOS 节奏审计）

**问题**：你现在的节奏没有"类型冷却"。刚写过一场情感重场戏，下一章还是情感重场——读者疲了，你也写不动。

**方案**：引入事件类型冷却矩阵。

定义 6 种事件类型及其冷却期：

| 事件类型 | 冷却期 | 示例 |
|---------|--------|------|
| ⚔️ 战斗/冲突 | 2章 | 丧尸遭遇、对抗、追杀 |
| 🎭 情感重场 | 2章 | 深度情绪戏、内心独白、重大关系变化 |
| 🏗️ 世界构建 | 0章 | 谈判、交易、探索新地点（越多越好） |
| 📖 信息揭示 | 1章 | 伏笔回收、背景揭露、重大发现 |
| 😌 日常/休憩 | 1章 | 做饭、洗澡、休息、闲聊 |
| 🔄 转折/意外 | 3章 | 重大背叛、死亡、反转 |

**规则**：
- 冷却期指"该事件类型结束后，需要相隔N章才能再次使用该类型"
- 如果连续2章写了战斗→第3章必须非战斗
- 如果连续2章写了情感重场→第3章必须是功能章或战斗章
- 冷却期可破例，但必须满足**双重条件**：(a) 该事件是之前伏笔的自然结果 (b) 你清楚知道自己在破例

**实操**：在写每一章之前，查看前2章的事件类型。如果本章事件类型落在冷却期内→换类型。

### 11.6 三层记忆架构（借鉴 Novel-Harness + 行业实践）

**问题**：当前框架的文件加载不分优先级，"必读"列表越来越长（MASTER_SETTING + current_state + 前3章全文 + nucleus-first-method + seven-knives + nucleus-to-technique-index）。上下文窗口被无关信息填满。

**方案**：重新分层：

| 层级 | 容量 | 内容 | 管理方式 |
|------|------|------|---------|
| 🔥 **HOT** | ~5K token | MASTER_SETTING 核心设定 + 当前角色位置 + 活跃伏笔（≤5条） | 永远在线，每章更新 |
| 🌡️ **WARM** | ~15K token | 前1章全文 + nucleus-first-method.md + style-fingerprint.md + 章型对应的技法文件 | 按章型加载 |
| ❄️ **COLD** | 存档 | 前3章全文 + chapter_summaries + 所有reference文件 | 仅当写中感觉"缺上下文"时按需检索 |

**加载规则**：
- 默认只加载 HOT + WARM
- 写中如果发现"这个角色/这个物品/这条线索我记不清了"→按需检索COLD
- 如果上下文接近 15K token 上限→先裁剪 COLD 层，不裁剪 HOT

### 11.7 平行人格预写（借鉴 NarrativeLoom 10人格 + BVSR 理论）

**问题**：当前框架是"单一路径写作"——你决定一个走向，然后写。没有"先让不同方向碰撞，再选最优路径"的步骤。

**方案**：遇到关键情节分岔点时，使用**平行预写**（不是每章都用，只用在关键决策点）：

```
分岔点：___（角色面临一个选择/剧情有多个可能的走向）

走向A：简述（1-2句）
走向B：简述（1-2句）
走向C（可选）：简述（1-2句）

选哪个：___（选的是最出人意料但又最符合角色性格的那个）
```

**规则**：
- 平铺 2-3 个走向，用 1-2 句话概括，不展开
- 不要选"最安全的"走向（那是AI的自然倾向）
- 不要选"最戏剧化的"走向（那是为了戏剧效果牺牲真实感）
- 选**最出人意料但又符合角色性格**的那个——这需要你真正理解角色，而不是计算概率
- 这个过程在脑子里完成，不写入正文，不超 60 秒

**使用频率**：每 3-5 章最多 1 次。用多了变成流程，流程会杀死直觉。

### 11.8 防幻觉一致性门禁（借鉴 Novel-Forge 21道Guard + InkOS Validator）

**问题**：当前框架的4e核验覆盖了逻辑和连续性，但没有专门针对"AI最常犯的幻觉错误"的门禁。

**方案**：在QC环节增加 5 道轻量门禁——每项检测耗时 < 10 秒，不查修辞不查节奏，只查事实性错误：

| 门禁 | 检测内容 | 判断方式 |
|------|---------|---------|
| 🚪 人名一致性 | 本章出现的所有人名是否在之前出现时用了同一称呼 | 扫描→对照前3章 |
| 🚪 位置连续性 | 角色是否在不可能的时间内出现在不可能的位置 | 当前state对照 |
| 🚪 物品存续 | 之前消耗/丢失的物品是否在本章"复活" | 快速扫描 |
| 🚪 时间箭头 | 时间是否倒流（非倒叙场景） | 昼夜/事件顺序检查 |
| 🚪 数字声称 | 距离/人数/天数/数量是否自洽 | 检查所有数字声称 |

**规则**：
- 这5道门禁在QC环节最后 30 秒完成
- 不要求 100% 通过（有些"不一致"是叙事需要），但在修改前要意识到
- 如果通过率 < 3/5 → 退回修改（说明幻觉风险高）

## 附录：v11.0 完整执行流程速查

### 写前（5分钟）

```
1. 判断章型（A/B/C）
   - 情绪？→ A型   动作？→ B型   功能？→ C型
2. 检查事件冷却（前2章的事件类型 vs 本章计划类型）
   - 冷却期内？→ 换类型或确认破例
3. 唯一画面测试（A/B型必做）
   - 读者合上眼会看到哪张画面？
4. 写前合同（3项，所有章型）
   - ①内心/事件/信息变化  ②悬而未决的问题  ③唯一画面
5. 按章型加载文件（HOT + WARM，不加载COLD）
6. 平行预写（仅关键分岔点，≤60秒）
```

### 写中

```
7. 按章型写（A型不查技法，B型查1次，C型白描）
8. 概率陷阱意识：写出乎角色性格但不出乎读者期待哪个？
   - 每章至少1处"读者预判不到"的走向
```

### 写后（10分钟）

```
9. Story Contract 核验（3项 PASS ≥ 2）
10. 反向刹车检查（新增冲突 ≥ 0，核心冲突未解决）
11. 叙事指纹检查（情绪标签≥1，闲笔≥1/3章，道德模糊≥1/5章）
12. 5道防幻觉门禁（通过 ≥ 3/5）
13. 自创公式检测（打火机/沉默/倒扣/手指松开——检查最近10章的重复率）
14. Anti-AI探测（仅发布前运行：段落等长/套话密度/公式化转场/对话标签单一）
```

### 每3章（3+1熔断）

```
15. 第4章完全免检——不判断章型，不查任何项目
    写完出声读一遍，自审一个问题：哪里不满意？
```

### 每10章

```
16. 更新文风指纹（句长中位数/TTR/感官分布/对话比——检查是否漂移）
17. 事件分布审计（最近10章的事件类型分布——是否有类型偏食）
```
